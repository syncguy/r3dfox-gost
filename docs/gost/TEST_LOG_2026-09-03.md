### Ownership established

The focused source-anchor gate confirms the Firefox 153 owners used for this experiment:

- `GetApplicationRestartSettings`, `RegisterApplicationRestart`, and `UnregisterApplicationRestart` are owned by `toolkit/xre/nsAppRunner.cpp::RegisterApplicationRestartChanged` and are tied to `PREF_WIN_REGISTER_APPLICATION_RESTART` through `Preferences::RegisterCallbackAndCall`;
- `GetNamedPipeServerProcessId` is owned by `accessible/windows/msaa/CompatibilityUIA.cpp::GetUiaClientPidsWin11::QueryThreadProc`, reached from `Compatibility::GetUiaClientPids` only on the `IsWin11OrLater()` path, while older Windows uses `GetUiaClientPidWin10`.

The Application Restart trio is optional Windows restart/relaunch integration rather than a normal browser startup/runtime prerequisite. The named-pipe API belongs to Windows 11 UI Automation client detection, not Firefox sandbox IPC.

### Remediation model under test

The representative legacy-XP variant implements the chosen policies:

- Application Restart trio: compile-time no-op for the legacy XP configuration, removing the optional feature as one unit rather than supplying three thunks;
- `GetNamedPipeServerProcessId`: resolve the real KERNEL32 export with `GetModuleHandleW` + `GetProcAddress`; if unavailable, return failure rather than fabricating a PID. When available, call the native API unchanged.

No broad YY `kernel32.lib` and no mechanical stub is involved.
